# At-Pet v1.4.0-beta1

## 密钥鉴权

「常规设置 → 安全选项」新增「密钥鉴权」，默认开启。取消勾选并应用后，重启 At-Pet 即可让本机 Hook、桥接插件和 MCP 免密接入。重新开启并重启后，原有密钥可继续使用。

免密模式下，任何本机进程都可以访问本地 API。API 仅监听回环地址，浏览器 Origin 和非回环 Host 请求会被拒绝。权限请求仍需在 At-Pet 中确认。

如果已安装的旧版发送端会在发出请求前强制读取密钥，请更新发送端。支持一键配置的 Agent 可以重新运行 At-Pet 的一键配置。详见[本地 API 鉴权说明](https://github.com/At-PetAdmin/At-Pet/blob/v1.4.0-beta1/docs/local-api-security.md)。

修复本地 API 在关闭仍有 SSE 订阅的连接时可能崩溃的问题。

## 下载

- `At-Pet-windows-amd64.zip` 适用于 Intel 和 AMD 64 位 Windows。
- `At-Pet-windows-arm64.zip` 适用于 Windows on ARM。
- 两个便携包均附有 SHA-256 校验文件。

## English

**General Settings → Security Options** now includes **Require a key for the local API**, enabled by default. Apply the setting and restart At-Pet. With authentication disabled, local hooks, bridges and MCP can connect without a key. Existing keys work again after you re-enable authentication and restart.

In this mode, any local process can access the API. The server listens on loopback and rejects browser Origin and non-loopback Host headers. Permission requests still require a decision in At-Pet.

Update installed senders that require a key before sending requests. For Agents that support one-click setup, rerun it in At-Pet. See the [local API authentication guide](https://github.com/At-PetAdmin/At-Pet/blob/v1.4.0-beta1/docs/local-api-security.md).

Fixed a potential crash when the local API shuts down with an open SSE subscription.

Windows amd64 and ARM64 portable ZIPs are available with SHA-256 checksum files.
